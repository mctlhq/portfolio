# Accessibility checklist (WCAG 2.2 AA)

One row per item named in issue #10 (P8). `pass` and `fail` are backed by a
committed file, a build-time script, or a direct read of the source named in
the note; `reviewer step` is work that genuinely needs a human (a screen
reader, a Lighthouse run, a browser) and is never treated as an acceptance
criterion — see AGENTS.md, "Issue contract".

| Item | Result | Note |
| --- | --- | --- |
| Keyboard operation of every `<details>` | pass | `src/components/Details.astro` renders a native `<details>`/`<summary>` with no JavaScript interception of focus, `Enter`/`Space`, or the arrow keys — the browser's built-in disclosure behaviour handles all of it. `src/styles/site.css` sets `.block > summary { display: list-item }` so the native marker (and therefore the native keyboard affordance) stays intact rather than being replaced by a custom control. |
| Focus visibility on links and buttons | pass | `src/styles/site.css` keeps a global `:focus-visible { outline: var(--focus-ring-width) solid var(--focus-ring); outline-offset: var(--focus-ring-offset); }` rule with no element carrying `outline: none`; asserted mechanically by `test/a11y.test.ts`. The ring colour is `--focus-ring: var(--accent)`, whose contrast against both surfaces is checked below. |
| Contrast in both themes | pass | `scripts/check-contrast.mjs` (wired into `npm test`) computes the WCAG relative-luminance contrast ratio for every foreground/background pair `site.css` renders — `surface-fg`, `surface-fg-muted` and `accent` over `surface-bg` and `surface-elevated`, plus `accent-fg` over `accent` — for both `data-theme` values, and, since issue #55 (Q2'), the class-less content link's `normal`, `:visited` and `:hover` colours over `surface-bg` and `surface-elevated` in both themes, plus the `@media print` `--accent` override over a forced white background. Twenty-seven pairs now clear their threshold, up from fourteen: the tightest is `accent` (the focus-ring colour, and, unvisited, the content-link colour) over `surface-bg` in light theme at 4.81:1 — now checked directly against the 4.5:1 text minimum via the content-link states, not only the 3:1 focus-ring minimum it already cleared; the print override measures 5.62:1 against white, up from the 3.64:1 an unpatched dark-theme `--accent` would give there. |
| `lang` correct on RU blocks | pass | `src/i18n/Lang.astro` renders `<span class="l ru" lang="ru">`; every Russian block on the site goes through this component or repeats the same `class="l ru" lang="ru"` pattern directly (the `<ul class="l ru" lang="ru">` blocks on the home and approach pages). Asserted by `test/a11y.test.ts` against `Lang.astro`, and by the existing `class="l en"` / `class="l ru"` parity check in `scripts/check-dist.mjs`. |
| Heading hierarchy | pass | Every page has exactly one `<h1>` (`src/pages/index.astro`, `work.astro`, `approach.astro`, `colophon/index.astro`, `404.astro`, and the two dynamic colophon routes). Since issue #98 (Q15), the home page's outline below its one `<h1>` is: `<h2>` for `#about` ("Who I am"), `#capabilities` ("What I do"), the two remaining `<Details>` summaries (`detailsRunSummary`, `detailsWorkSummary` -- `Details.astro`'s `heading` prop still carries an `<h2 class="block-title">` inside `<summary>`) and `#contact` ("Get in touch"); `<h3>` for each of the three capability terms. The third, previously-open `detailsContactSummary` disclosure is gone -- replaced by the always-visible `#contact` section -- so the built page now carries zero `<details open>` and exactly two `<summary><h2` openings, down from one and three. `work.astro`'s two groups and `colophon/index.astro`'s three sections keep their own `<h2>`; the journal and ADR pages keep their section headings; `approach.astro`'s and `work.astro`'s `<Details>` summaries are left as plain `<summary>` text, not headings (out of scope, see the proposal's open questions). `checkHomePage()`/`checkApproachPage()` in `scripts/check-dist.mjs` assert the built `<summary><h2` count is exactly two on `dist/index.html` and exactly zero on `dist/approach/index.html` and `dist/work/index.html`. No page skips a level or uses a heading for styling alone. |
| Link purpose | pass | Every link's accessible text comes from `src/i18n/ui.ts` (`ctaWork`, `ctaColophon`, `navHome`/`navWork`/`navApproach`/`navColophon`, `journalBackToColophon`, `adrBackToColophon`, `notFoundHome`, …) or names its destination directly (`hello@dmitriimashkov.com`, a project's own name in `ProjectCard.astro`, an ADR's own title). `src/components/Footer.astro`'s GitHub anchor points at `https://github.com/mctlhq/portfolio` — the repository, not the organisation — with its accessible text the bilingual `footerGithubLabel`; its release anchor's entire accessible text is the bare version number read from `package.json` (`{pkg.version}`), with the `footerReleaseLabel` "Release" text sitting outside the anchor, in a preceding `<span>`. None reads "click here" or "read more". |
| Bypass blocks (skip link) | pass | `src/layouts/Base.astro` renders `<a class="skip-link" href="#main">` as the first child of `<body>`, before `<Nav />`, and `<main id="main" tabindex="-1">` hoisted into the same layout so every one of the seven pages carries the same landmark. Clipped out of layout until `:focus` (`.skip-link` / `.skip-link:focus` in `src/styles/site.css`), with no `animation` or `transition` (`test/a11y.test.ts`). `checkNavigationState()` in `scripts/check-dist.mjs` fails the build if any built page is missing `<main id="main" tabindex="-1">` or the `href="#main"` anchor does not occur before the first `<nav`. Confirming focus actually lands on activation is a reviewer step (browsers differ on a non-otherwise-focusable fragment target), per `AGENTS.md`. |
| Current page indication | pass | `src/components/Nav.astro` derives the current path from `Astro.url.pathname` at build time (no client-side script) and emits `aria-current="page"` on an exact match, `aria-current="true"` on the `Colophon` link for a journal or ADR page, and no attribute on the 404 page. `src/styles/site.css`'s `.site-nav a[aria-current]` rule adds both a colour and an underline, so colour is never the sole indicator. `checkNavigationState()` in `scripts/check-dist.mjs` counts exactly one `aria-current` inside `.site-nav` on every main, journal and ADR page and zero on `404.html`; `test/nav.test.ts` asserts the same derivation and the four literal nav anchors at the source level. |
| Group naming in the active language | pass | Both toggle groups (`src/components/LangToggle.astro`, `ThemeToggle.astro`) carry `role="group"` and `aria-labelledby` pointing at a `.visually-hidden` bilingual `<Lang>` span, replacing the slash-joined bilingual `aria-label` that used to read out both languages at once. The `site-nav` `<nav>` and the home page's `.ctas` `<nav>` use the same `aria-labelledby` mechanism. `checkNavigationState()` fails the build on any remaining `aria-label` value that mixes a Latin and a Cyrillic letter, exempting only the out-of-scope `.table-scroll` region on `dist/colophon/index.html`; `test/nav.test.ts` asserts `role="group"` and `aria-labelledby` at the source level and the absence of any remaining `${…en} / ${…ru}` template literal in `src/components/`, `src/layouts/` and `src/pages/index.astro`. |
| SVG text alternatives | pass | The two `<CycleDiagram>` variants (`src/components/CycleDiagram.astro`) each carry `role="img"`, `aria-labelledby` resolving to one `<title>` and one `<desc>` inside the same `<svg>` — enforced mechanically by `checkApproachPage()` in `scripts/check-dist.mjs`, which fails the build on a missing role, a dangling `aria-labelledby` token, or a wrong `<title>`/`<desc>` count. `public/og.svg` also carries `role="img"` and a `<title>`/`<desc>` pair, though it is not covered by the build check since it is a static `public/` asset the build never inspects directly for that shape. Since issue #50 (Q6), `og.svg` is not itself what the page links to: it is the build-time source `scripts/render-og.mjs` rasterises to `dist/og.png` via `@resvg/resvg-wasm`, and `/og.png` is the value the `og:image`/`twitter:image` meta tags name (`checkOgImageMeta()` in `scripts/check-dist.mjs` asserts the two tags agree and resolve to a file under `dist/`). |
| Target size at least 24px | pass | `src/styles/site.css` sets `min-block-size: 44px` — above the 24px CSS Working Group "AA equivalent" floor named in the issue — on `.site-nav a`, `.site-footer a`, `.cta` and `.block > summary`, and `min-block-size: 32px` on `.toggle-group button`, the two auxiliary language and theme segments in the header; both are above the 24px floor and both are asserted by `test/a11y.test.ts`. |
| No motion | pass | `src/styles/site.css` declares no `animation` or `transition` property anywhere in the file (grep-verified and asserted by `test/a11y.test.ts`); the only visual change on interaction is the `[aria-pressed='true']` colour swap on the language/theme toggles and the `:focus-visible` outline, both instantaneous. |
| Screen-reader sweep (NVDA/VoiceOver) over all four pages, both languages | reviewer step | Needs an actual screen reader; not reproducible from source or from a build script. |
| Visual focus confirmation (tab through every page, both themes) | reviewer step | Needs a real browser viewport to confirm the ring is visually legible in context, beyond the numeric contrast ratio `check-contrast.mjs` already proves. |

No item above is marked `fail`, so there is no documented exception or
follow-up issue to open at this time.

## Re-walk log

- Issue #49 (Q5, navigation state, disclosure defaults and accessibility
  affordances): rewrote the "Heading hierarchy" row for the three new
  home-page `<h2>` disclosure titles, and added rows for "Bypass blocks (skip
  link)", "Current page indication" and "Group naming in the active
  language" to cover the skip link, `aria-current` navigation marking and the
  `role="group"`/`aria-labelledby` toggle and `<nav>` naming this cycle added.
- Issue #98 (Q15, conversion-first home): rewrote the "Heading hierarchy" row
  again -- the home page gained `#about` and `#capabilities` `<h2>` sections
  (with `<h3>` capability terms) and a visible `#contact` `<h2>` section,
  while the third `<Details>` disclosure (`detailsContactSummary`, previously
  the one open-by-default block) was removed outright, so the built page's
  `<summary><h2` count drops from three to two and its `<details open>` count
  drops from one to zero.
- Issue #103 (Q16, compact segmented language and theme): the language and
  theme toggles moved onto the navigation line, right-aligned inside a
  `.site-header` flex row, and each control's two buttons joined into one
  bordered segmented control with a single internal divider, dropping the
  auxiliary controls' target size from 44px to 32px -- still above the 24px
  floor and the WCAG 2.2 AA 2.5.8 minimum. `overflow: hidden` was deliberately
  not used on `.toggle-group` to round its ends, because it would clip the
  `outline-offset` focus ring on the first and last segment; per-segment
  corner radii give the same shape without clipping.
