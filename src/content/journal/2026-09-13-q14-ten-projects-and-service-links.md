  en: "The owner decided four of the fourteen entries on /work/ did not belong there: one whose slug read as a one-letter typo of a remaining platform entry, two retired services, and one whose rendered commit and release counts came from an upstream fork rather than from the owner's own work. All eight files (en and ru) for those four entries were removed, and the remaining twenty files were renumbered so order runs 1..10 once per language, five platform and five product. The retired entry with no public repository was the only one with private: true and no repo:, so the private-repo capability -- the private field, ProjectCard.astro's private branch and the workPrivateRepo string -- now proves itself against a fixture tree built with a real astro build instead of against one production entry, including a mutation control that fails if the chip were ever driven by a missing repo: instead of the explicit field. The seerrsense summary claimed integration with Seerr, Radarr and Sonarr; the code integrates only Seerr, so the summary was corrected on both languages and a bullet was added naming Seerr as the one upstream that in turn drives Radarr and Sonarr. Six projects that run a public service gained a links entry beside their repository link -- mctl-portal, mctl-design, mctl-telegram, seerrsense, mctl-academy and mctl-loyalty -- in the same shape mctl-api already used for its Docs link. The colophon's build-and-deploy chain dropped its note about a temporary rehearsal host, which described a migration state rather than the standing chain and published an internal host name; decommissioning that host itself is a separate, dated action through the mctl and Cloudflare MCP tools and is out of scope here. Finally, the counts test/projects.test.ts and test/work.test.ts encode for the project set were pulled into one shared test/support/expected-projects.ts module so a list and a count that must agree cannot drift apart again."
